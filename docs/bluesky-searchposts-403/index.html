Bluesky searchPosts returns 403 Forbidden: why it happens and how to fix it

The error

GET https://public.api.bsky.app/xrpc/app.bsky.feed.searchPosts?q=apify&limit=1 answers 403 Forbidden for unauthenticated callers, especially from GitHub Actions and other datacenter IPs. Paging with the returned cursor can also fail on page 2. (We re-ran the first call on 2026-10-22 and got 403.)

Free fix 1: use the api.bsky.app host

The same endpoint on api.bsky.app answered 200 without login when we tested it on 2026-10-22:

curl -s "https://api.bsky.app/xrpc/app.bsky.feed.searchPosts?q=apify&limit=25&sort=latest"

Bluesky can change this at any time and may block shared IPs again. If it does, sign in with an app password and send the access token as a Bearer header to your own PDS or bsky.social.

Free fix 2: page by time window, not by cursor

Take the oldest record.createdAt from each page and pass it as until for the next request:

until="2026-10-22T00:00:00Z"
for i in 1 2 3; do
  curl -s "https://api.bsky.app/xrpc/app.bsky.feed.searchPosts?q=apify&limit=100&sort=latest&until=$until" > page$i.json
  until=$(python3 -c "import json;p=json.load(open('page$i.json'))['posts'];print(min(x['record']['createdAt'] for x in p))")
done

Posts are returned newest first with sort=latest; dedupe on uri because the boundary post can repeat.
