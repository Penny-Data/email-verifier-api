Extract frames from a video URL via API

Send direct links to video files (mp4, webm, mov, mkv) and get back still images: one every N seconds, N evenly spaced frames, or one at each scene change. It runs on the Apify actor pennydata/video-frame-extractor (ffmpeg inside) and you call it with a single HTTP request, with no ffmpeg install on your side. An optional contact sheet gives one grid image per video.

Why this page: "extract frames from video" is a query people run on the Apify Store, where the top rival actor (kantolabs) showed about 119 users and 92 monthly users when we last read the Store API on 2026-10-21. This is a cheaper pay-per-frame option with a built-in spend cap.

Honest notes

It needs a link to the video file. YouTube, Vimeo, TikTok and other page links are not supported. Only process videos you have the right to use. Scene mode relies on ffmpeg's scene score, so tune sceneThreshold (default 0.3) for your footage; if no scene change is found the video is reported as failed and not charged.

curl

Get your token at console.apify.com/account/integrations and export it as APIFY_TOKEN.

curl -sS -X POST \
  "https://api.apify.com/v2/acts/pennydata~video-frame-extractor/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "videoUrls": ["https://interactive-examples.mdn.mozilla.net/media/cc0-videos/flower.mp4"],
    "mode": "interval",
    "intervalSeconds": 2,
    "format": "jpg",
    "contactSheet": true,
    "maxCostUsd": 0.5
  }'

Node.js (18+, no dependencies)

const res = await fetch(
  "https://api.apify.com/v2/acts/pennydata~video-frame-extractor/run-sync-get-dataset-items",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.APIFY_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      videoUrls: ["https://example.com/clip.mp4"],
      mode: "count",      // "interval" | "count" | "scene"
      frameCount: 8,      // used by mode "count"
      format: "jpg",      // "jpg" | "png"
      maxWidth: 1280,
      maxCostUsd: 0.5,
    }),
  }
);
if (!res.ok) throw new Error(`Apify ${res.status}: ${await res.text()}`);
for (const row of await res.json()) {
  if (row.status !== "ok") console.error(row.videoUrl, row.status);
  else console.log(row.type, row.timestampSec, row.frameUrl);
}

Output

One dataset row per frame: videoUrl, status, type (frame or contact-sheet), timestampSec, frameUrl (public URL of the image in the run's key-value store), width, height, durationSec. Failed or skipped videos get a row with status "failed" or "skipped" and a reason. The synchronous endpoint has a time limit, so for long or many videos start the run with the asynchronous endpoint (see the Apify API docs).

Limits

Interval frames are exact to the nearest decodable frame. Up to 500 frames per video in count mode, 1000 per video in any mode, width up to 3840 px, files up to 1.5 GB. Private network addresses are blocked. Frame URLs follow your Apify storage retention.
